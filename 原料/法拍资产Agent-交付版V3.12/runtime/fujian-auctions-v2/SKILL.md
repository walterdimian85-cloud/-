# 福建法拍房整理

## 运行边界

- 仅采集福建省`住宅用房、商业用房、工业用房`下的`即将开始、已结束`；不扫描`正在进行`。
- 阿里破产拍卖/非标准详情布局如能明确读取房源字段，按页面证据采集，不得只因布局不同判定为加载异常。若详情返回后落到`i.taobao.com/my_itaobao`，保留当前列表卡片信息和链接至待人工复核，将其标记为已处理；重新打开列表入口，从已保存队列的下一条继续，不循环重试或阻塞高水位。
- 使用Microsoft Edge和独立持久Profile，顺序低频访问。
- 只读使用账号。不得报名、出价、收藏、提醒、联系机构或修改账号。
- 不自动处理账号密码、短信码、验证码或滑块；需要时暂停并让用户人工完成。
- 阿里登录或滑块消失不等于验证成功。只有重新打开原目标列表/详情并识别到目标页有效内容后才可继续；验证后暂时落到淘宝首页、个人页、空壳页或仍未加载目标内容时，应保持人工等待状态并以不少于5秒的低频间隔重试原目标。若验证过程中标签页或浏览器会话被关闭，必须让监工重建同一持久化Profile并从断点续爬，不得把后续各组批量记为失败，也不得重爬已完成平台和已保存链接。
- 不估算缺失字段，不以价格关系决定成交，不以土地类面积代替建筑面积。

开始前读取：[字段和增量规则](references/field-rules.md)。操作阿里或京东时读取：[平台规则](references/platforms.md)。环境安装读取：[安装与环境](references/setup.md)；中断时读取：[中断恢复](references/recovery.md)；登录和打包前读取：[安全边界](references/security-rules.md)。

V2开发与回归必须保留[V1.1.0冻结基线](references/v1-baseline.md)。面积、标的名称和小区名称统一调用`src/extractors/`中的模块；不得在采集器或工作簿适配器中复制第二套业务规则。字段证据保存在记录的`_fieldEvidence`中，不新增默认Excel列。

## 首次运行目录门禁

1. 第一次执行采集前，先询问用户：“今后爬取的房源信息希望保存在哪个文件夹？”
2. 用户未明确提供结果目录时，不得打开拍卖网站，不得自行猜测路径，也不得把结果写入Skill目录。
3. 收到路径后使用`--output-dir DIR`运行。CLI会把该选择保存到外部`stateDir\output-settings.json`，以后未再次指定时自动复用。
4. 用户明确更换目录时，再次传入`--output-dir DIR`并更新保存设置。状态目录、Edge Profile与结果目录仍须位于Skill目录之外。

## 高水位门禁

每个平台必须具有3个类别×2种状态共6条前一日高水位；选择两个平台时必须有12条。

1. 在打开Edge前检查所选平台全部高水位。
2. 缺少任一项时停止，并明确指出平台、类别和状态，例如：“还缺少前一日京东拍卖工业用房类别中已结束的最新数据链接，请您提供链接。”
3. 不猜测高水位，不在缺失时继续扫描。
4. 用`seed-anchors`导入用户提供的链接。
5. 只有所有列表、详情、工作簿和质量检查成功时才推进高水位。

## 试运行高水位

- 用户声明“试运行”时，不得自动创建、猜测或从生产状态复制影子高水位。
- 先确认用户要测试的平台、类别和状态，再明确要求用户提供该组合的高水位链接；例如：“本次试运行还缺少阿里资产住宅用房—即将开始的高水位链接，请您提供链接。”
- 收到链接后，将其写入位于生产目录之外的独立试运行状态目录。试运行必须使用`--dry-run`，不得推进或修改生产高水位。
- 用户要求一次试跑多个组合时，逐项列出缺少的高水位；所选组合全部齐全后才能打开网站。
- 试跑结束后报告`priorAnchor`、`firstUrl`、`anchorFound`、扫描页数、新增详情数、`failures`、`dryRun`、`stateAdvanced`以及生产`state.json`运行前后校验值。

## 运行命令

先执行：

```powershell
node bin/auction-cli.mjs help
```

导入高水位：

```powershell
node bin/auction-cli.mjs seed-anchors --platform all --anchors-file .\前一日高水位.json --state-dir .\path
```

每日正式采集默认使用监工模式：

```powershell
node bin/auction-cli.mjs supervise --config .\config\example.json --output-dir "<用户指定的结果目录>"
```

监工模式在本地持续检查心跳、断点和结果，出现可恢复故障时按原命令有限重试；不得添加`--restart`。详细规则见[本地监工与自动续爬](references/supervisor.md)。直接`run`仅用于诊断或用户明确要求不启用监工时。命令行参数覆盖配置文件。Codex环境可选择`--workbook-adapter codex`；其他具备Node和Edge能力的宿主使用`standard`。

## 确定性流程

1. 读取同日期、同状态目录的`采集进度.json`，恢复队列并跳过已完成链接；只有用户明确要求时才使用`--restart`。
2. 刷新状态库中尚未得到结束结果的已有链接，但不扫描`正在进行`列表。
   - 用户明确要求只按新提供的前一日高水位采集、不追溯更早历史记录时，使用`--skip-historical-refresh`跳过本轮历史刷新，直接进入12组列表增量扫描。不得擅自启用该参数。
3. 按平台→类别→状态扫描：
   - 阿里即将开始：`最新发布`；阿里已结束：`结拍时间由近到远`。
   - 京东固定竞价项目、诉讼资产+刑案资产、福建省和单一类别；预告中点击一次最新发布，已结束点击两次结束时间。
4. 每处理一条详情立即原子保存JSON进度，并按配置刷新采集中的Excel。
5. 以规范链接为唯一键；同一标的更新，不重复新增。
6. 全部完成后只生成`即将开始、成交标的、流拍标的`三张业务表，再按平台（阿里→京东）→城市拼音→区域拼音→拍卖时间倒序排序。三张表统一使用8月4日样式：浅绿色表头、白色数据背景、无交替底色，中文宋体、英文字符优先Times New Roman，冻结首行和前三列。待复核项继续保存在`待人工复核.json`，不生成Excel分表。
7. 保存至`房源整理结果\YYYYMMDD\YYYYMMDD新增房源信息.xlsx`，同时保存运行结果、证据、复核清单和恢复进度。

## 字段要求

`即将开始`输出18列：所在省份、城市、区域、标的名称、小区名称（仅供参考）、标的类型、平台、发拍次数、拍卖时间、是否成交、处置法院、面积/㎡、起拍单价-元/㎡、起拍价格、评估价、折扣率(%)、备注、网站链接。尚未开拍的标的不输出`成交金额`。

`成交标的`输出23列：上述共同字段，并增加`成交金额、溢价率、成交单价、竞买记录、报名人数`。所有业务表中的评估价均来自明确价格标签，优先级为`评估价、评估总价、市场评估价、评估价值、市场价`；所有评估类标签均优先于市场价。先读取详情页标签及邻接金额，公告中同一价格语境的明确标签仅作后备。网页内部和Excel均按元保存；`折扣率=起拍价格/评估价`。`溢价率=(成交金额-起拍价格)/起拍价格`；`成交单价=成交金额/面积`。三个比率或单价指标必须使用Excel公式，不得硬编码计算结果。

`流拍标的`不输出`成交金额、溢价率、成交单价`，保留起拍价格、竞买记录和报名人数等可复核信息。成交标的和流拍标的的`拍卖时间`均使用页面明确的最终竞拍结束时间，优先结果区，再回退至竞买公告的时间范围；不得按固定时长推算。

- 网站住宅细分为`住宅、别墅、车位`；商业、工业分别输出`商业、工业`。
- 标的名称删除省、市、区县等前置行政区划，但保留街道、社区、镇、乡、村等具体位置；清洗后必须尽可能保有“具体位置+项目/小区+楼栋/房号”。括号采用“明确无用才删除，不确定默认保留”，避免名称只剩道路门牌号。标的名称保留`一期、二期、A区`等分期分区；小区名称统一归并到不含分期分区的总项目主名，不按离楼栋编号远近选择。完整商业街属于有效项目；只有片区/安置房/地块且无正文证据时回退`商住小区`。工业只把正式园区、集中区或厂区项目作为名称，公司名及泛称回退`工业区`。福州、泉州小区优先按人工词典作城市/区域约束匹配，详见[标的名称与小区名称规则](references/title-community-rules.md)。
- 默认不读取、不检查、不输出债权人和债务人。用户明确要求时启用`--include-parties`，恢复两列并按已有关键词提取。
- 阿里成交仅依据`本场已结束/本场已流拍`；京东仅依据灰色结果区`已成交/已流拍`。
- 仅对`已结束`提取竞买记录和报名人数；`即将开始`表不设置这两列。阿里读取`N人报名`与`竞买记录（N）`，并将错写的`应买记录（N）`按竞买记录处理；京东将`出价记录（N）`明确映射为Excel的`竞买记录`，并兼容`竞买记录/应买记录/竞价记录`标签。流拍竞买记录固定为0，但报名人数仍读取页面且可能大于0；已成交任一数值缺失或为0时进入复核，不得推断。
- 面积介绍区未命中时不得提前停止，继续检查竞买公告、调查表和其他既定来源。兼容`平米`及非规范`m2`；明确`总数/总共`优先于括号内分项。多个同类房室合并拍卖可按证据求和并在备注保留分项，但不得与储藏间、附属物、车位、车库或土地面积混加。
- 面积依照公告文字/表格→调查表→介绍/首页→帮助中心取值，兼容标签和值同一行相邻单元格、表头和值跨行同列；单位兼容`㎡、m²、m2、平方米、平方公尺`及平台误写的`105.41/㎡、105.41/m²`。阿里读取`标的物介绍`表格，京东读取`拍卖标的物调查情况表/标的物介绍`表格；排除宗地、土地、占地和分摊面积。
- 起拍单价使用Excel公式`ROUND(起拍价格/面积,2)`；面积不是正数时留空。
- 起拍价格优先读取详情页邻接`起拍价`。仅当发拍次数已可靠识别为`变卖`且起拍价缺失时，才读取邻接`变卖价`并将其作为起拍价格；普通一拍、二拍不得用变卖价。详情页缺失后才按同一阶段规则回退列表页和竞买公告。
- 面积总数与分项必须按[面积表达目录](references/area-expression-catalog.md)判定：连续同类主标的可以按证据求和；主住宅与储藏间、附属间、柴火房、车位或车库同时列示时，面积列只写主住宅面积，附属物面积按`主住宅：…㎡；储藏间：…㎡。`写入备注，不再因这一已确定口径单独进入待复核。`套内、专有、分摊、红线外、未列入拍卖范围、相关推荐`中的面积不得替代当前标的面积。
- 面积未找到时检查详情页PDF/Word链接：发现评估报告则备注`需打开网页评估报告提取面积`，没有评估报告则备注`未找到评估报告`。遇到`71.56/874.64共946.2㎡`等无法确认含义的多值表达，面积写`未找到`，备注保留原文并追加`，人工需复核`；不得自行选择数值。

## 复核与交付

- 优先检查面积、法院、拍卖时间、成交结果、起拍价格、评估价和成交金额。
- 页面空壳、登录页、结构无法确认或关键字段缺失时记录证据并进入复核；不要无限刷新。
- 面积存在无法由既定“主住宅优先、附属物写备注”规则解决的其他口径冲突时，即使已经提取到数字也必须进入复核，不得以“非空”视为字段正确。
- 交付时报告总数、即将开始数、已结束数、待复核数、失败数和高水位是否推进。
- 打包时排除Profile、Cookie、历史记录、每日结果、临时文件和检查副产物。

## 跨模型调用

模型负责理解任务、补齐高水位、调用CLI、等待人工认证和解释结果；CLI负责页面、字段、高水位、断点和Excel规则。只有聊天能力而不能执行命令、访问文件或启动Edge的模型不得声称已完成采集。模型适配提示位于`adapters/`。

在WorkBuddy中运行时，先读取[WorkBuddy运行与验证](references/workbuddy.md)和`adapters/workbuddy/prompt.md`，再按所选模型读取HY3或DeepSeek补充提示。必须导入整个Skill目录并先通过能力探针；不得只导入提示文件或让模型重写采集逻辑。

用户要求试运行时，还必须读取[试运行规则](references/trial-run.md)。
