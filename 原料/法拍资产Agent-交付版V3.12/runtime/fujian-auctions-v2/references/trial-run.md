# 试运行规则

## 目的

试运行只验证宿主模型、Edge、页面读取、字段解析和工作簿生成能力，不推进生产状态。

## 两段式交互

1. 用户声明要试运行时，先确认平台、类别和状态。
2. 对每个所选组合，要求用户提供一条当前可在列表中找到的高水位链接。
3. 未收到全部所需链接前，不打开拍卖网站。
4. 不得自动创建、猜测、搜索或从生产`state.json`复制试运行高水位。
5. 将用户链接写入独立试运行目录，例如`workbuddy-smoke-state\<model>-<date>`；其中不得包含Edge Profile。
6. 使用独立输出目录、`--dry-run`、低频模式和有界的`max-items`、`max-pages`运行。

单组合示例提问：

> 本次试运行还缺少阿里资产住宅用房—即将开始的高水位链接，请您提供链接。收到后我会把它写入独立试运行状态，不会修改生产高水位。

## 通过条件

- CLI真实退出代码为0。
- `anchorFound=true`且`failures=[]`。
- `dryRun=true`且`stateAdvanced=false`。
- 生产`state.json`运行前后SHA-256一致。
- 总表新增数据行不超过`max-items`；若高水位就是首条，0条新增也是合法结果。
- 未发生报名、出价、收藏、提醒、联系机构或账号修改。

若用户希望验证“确实能落一条数据”，应由用户提供列表第二条或更靠后的高水位；模型不得为了制造新增记录而自行选择锚点。
