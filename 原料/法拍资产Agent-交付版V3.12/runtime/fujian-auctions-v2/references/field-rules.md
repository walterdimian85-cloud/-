# 字段与增量规则

## 输出工作表

- `即将开始`：站点该状态筛选取得、尚未得到结束结果的记录。
- `成交标的`：站点“已结束”中详情明确已成交的记录，保留成交金额、溢价率、成交单价、竞买记录和报名人数。
- `流拍标的`：站点“已结束”中未成交、流拍、撤回、中止或暂缓的记录，不输出成交金额、溢价率和成交单价。
- 最终Excel只保留`即将开始`、`成交标的`和`流拍标的`三张业务表，不生成`总表`或`待复核`分表。待复核链接及原因继续写入`待人工复核.json`。
- 所有业务表采用8月4日样式：浅绿色表头、白色数据背景，不使用交替底色；中文字体为宋体，英文字符优先Times New Roman；冻结首行和前三列。
- 数据表排序：平台（阿里资产→京东拍卖）→城市拼音升序→区域拼音升序→拍卖时间倒序→网站链接。

## 字段定义

| 顺序 | 字段 | 规则 |
|---:|---|---|
| 1 | 所在省份 | 固定为`福建省` |
| 2 | 城市 | 福建地级市，如`泉州市` |
| 3 | 区域 | 区、县或县级市，如`鲤城区、晋江市` |
| 4 | 标的名称 | 摘取房屋坐落主干；去除阶段标签、省/市/区县等前置行政区划、公司名下/坐落于前缀、权证号和`可贷款`提示；保留街道、社区、镇、乡、村等具体位置。括号内原址、现址、另行门牌号及权证说明删除；括号内含小区/楼盘、楼栋/幢、单元、房号、商铺、车位、厂房/园区或`一期、二期`等项目定位信息时完整保留。若删除括号会使名称只剩道路门牌号，优先保留能够识别小区和楼栋的括号内容；删除汉字与相邻数字/字母编号之间无意义的空格 |
| 5 | 小区名称（仅供参考） | 证据顺序为详情/公告明确字段→清洗标题正文词典→含已删除括号的原始标题→人工确认地址映射→标题后处理。标的名称保留分期分区，小区列统一去掉`一期、二期、A区、二区`等后缀并输出总项目主名；多个候选时不按离楼栋编号远近选择。完整商业街属于有效项目；只有片区/安置房/地块且正文无明确小区时写`商住小区`。工业有正式园区、集中区或厂区项目时保留正式名称，只有公司名或泛称时写`工业区` |
| 6 | 标的类型 | 见“标的类型细分” |
| 7 | 平台 | `阿里资产`或`京东拍卖` |
| 8 | 发拍次数 | `一拍、二拍、再次拍卖、变卖`；无法确认写`待核验` |
| 9 | 拍卖时间 | `即将开始`取明确开拍时间；`成交标的`和`流拍标的`均取最终竞拍结束时间。兼容`结束时间 2026/07/31 10:00:00`、`2026-07-31 10:16:12结束`及日期和时间之间无空格的写法；存真实日期值，Excel只显示`月-日`，不得推算 |
| 10 | 是否成交 | 见“状态与金额” |
| 11 | 处置法院 | 页面处置机构或公告中的人民法院全称 |
| 12 | 面积/㎡ | 数值；位置优先级：竞买公告标的物文字/表格→标的物调查表表格→标的物介绍/平台首页简介→帮助中心`这套房关键信息是什么？`；同一位置关键词优先级：产权总面积→建筑总面积→建筑面积→面积 |
| 13 | 起拍单价-元/㎡ | Excel公式`ROUND(起拍价格/面积,2)`；面积不是正数时留空 |
| 14 | 起拍价格 | 人民币元数值。先按详情页邻接标签提取`起拍价`；只有发拍次数已可靠识别为`变卖`且起拍价缺失时，才将邻接`变卖价`映射为起拍价格。之后按相同阶段规则回退详情页正文、列表页和公告；普通一拍、二拍不得使用变卖价 |
| 15 | 评估价 | 网页解析和Excel均以人民币元保存，与起拍价格口径一致。按`评估价、评估总价、市场评估价、评估价值、市场价`顺序检索；所有评估类标签均优先于市场价。优先读取详情页标签及相邻数值，公告中同一价格语境的明确标签只作后备；不得用起拍价、保证金或其他金额代替 |
| 16 | 折扣率(%) | 所有业务表均用Excel公式计算：`起拍价格/评估价`，按百分比显示；任一价格缺失或评估价不大于0时留空 |
| 17 | 成交金额 | 阿里成交优先按顶部`拍下价`标签读取邻近数值；流拍取0；未结束取0 |
| 18 | 溢价率 | 仅成交标的表设置；Excel公式`(成交金额-起拍价格)/起拍价格`，按百分比显示，起拍价格无效或为0时留空 |
| 19 | 成交单价 | 仅成交标的表设置；Excel公式`ROUND(成交金额/面积,2)`，面积无效或不大于0时留空 |
| 20 | 竞买记录 | 仅已结束记录设置；流拍固定为0；兼容`竞买记录/应买记录/竞价记录/出价记录`，其中`应买记录`视为网页错写，京东`出价记录`映射为本字段 |
| 21 | 报名人数 | 仅已结束记录设置；从`N人报名/报名人数N`读取，流拍也可能大于0 |
| 22 | 备注 | 默认留空。页面同时列示主住宅与储藏间、附属间、柴火房、车位或车库时，面积列只写主住宅面积，本列按`主住宅：93.59㎡；储藏间：5.77㎡。`记录各分项 |
| 23 | 网站链接 | 去除跟踪参数后的规范详情页链接，也是唯一键 |

默认表格不含债权人、债务人。只有用户明确提出采集这两项时才启用`--include-parties`，并在`起拍单价-元/㎡`之后恢复两列：

- `债权人`：阿里优先取抵押权人及“抵押于/抵押给”等具名主体；无可靠文字写`未找到`。
- `债务人`：阿里优先取调查表所有人/权利人标签，其次取债务人/被执行人；脱敏姓名按原文保留。

不输出独立的`溢价`金额；`溢价率`只在`已结束`表中输出。

## 标的类型细分

站点筛选仍使用`住宅用房、商业用房、工业用房`，但Excel输出更细：

- 站点`住宅用房`：
  - 名称含`车位`或`停车位`→`车位`；
  - 名称含`别墅`→`别墅`；
  - 其他全部→`住宅`，包括复式、楼中楼、住宅带储藏间、公寓、普通住宅等。
- 站点`商业用房`→`商业`，包括店面、写字楼、办公及被平台归入商业用房的地下车库车位。
- 站点`工业用房`→`工业`，包括厂区不动产、工业厂房、仓储物流。

## 面积、价格与标题证据

- 新增兼容`平米`及非规范`m2`单位；`总241.34m2（……分项……）`和`建筑面积总共为97.07平方米（其中……）`均取明确总数，不重复汇总括号内分项。
- 多室合并拍卖且页面逐项列出两个或以上同类房号/室号及各自建筑面积时，汇总同类主标的面积，并把页面分项原文写入`备注`。出现储藏间、附属物、车位、车库、柴火房或土地面积时禁止套用多室求和规则。
- 标题明确列出两个或以上同类店面、店铺、商铺、房号或室号，正文以`4063店面27.18平方米、4064店面27.8平方米……`等紧邻格式逐项给出面积时，必须逐一核对标题编号与正文编号，全部对应后汇总建筑面积并在备注保留分项和合计；不得把标题未包含的分项加入总面积。
- 标的物介绍未命中面积时继续检查竞买公告、调查表和其他既定来源；只有全部受支持来源均无面积证据时才写`未找到`。

- 面积接受带`㎡、平方米、平方公尺、m2、m²`单位的明确表述；单位前多写斜杠的`105.41/㎡、105.41/m²`也有效，斜杠只视为格式噪声。兼容`共39.2平方米`、`建筑面积共225.97平方米`等写法。表格既要读取“标签和值同一行相邻单元格”，也要读取“`建筑面积（m2）`表头与数值跨行同列”；阿里`标的物介绍`和京东`拍卖标的物调查情况表/标的物介绍`均适用。不得把其他列的权证号或土地面积误作建筑面积。同一证据位置按`产权总面积→建筑总面积→建筑面积→面积`匹配。
- 同一页面出现多个面积时，先按`竞买公告标的物文字→调查表→标的物介绍/首页简介`选择证据位置，再按上述关键词优先级取值；前三处均未找到时，访问同标的帮助中心，在`这套房关键信息是什么？`区域读取`建筑面积`作为最后回退。不得用宗地面积、土地面积、占地面积、分摊面积或估算值替代。
- 页面同时列明主住宅和附属物时，不论是否另列合计值，`面积/㎡`只保存主住宅面积，用于计算主住宅起拍单价；储藏间、附属间、柴火房、车位、车库等面积写入`备注`。不得把附属物面积加到面积列，也不得丢弃附属物证据。
- 详情页未提取到面积但存在PDF或Word评估报告/评估附件时，面积写`未找到`，备注写`需打开网页评估报告提取面积`；只记录附件链接，不自动下载、推断或OCR。
- 详情页未提取到面积，且没有发现PDF或Word评估报告时，面积写`未找到`，备注写`未找到评估报告`。
- 页面出现`71.56/874.64共946.2㎡`等多个面积值但缺少可验证字段含义时，不选择其中任一数值：面积写`未找到`，备注原样写`71.56/874.64共946.2㎡，人工需复核`，并进入待复核。
- 阿里规则信息栏的`起拍价/变卖价`标签邻近数值是起拍价格最高优先证据；读取`pm-ui="mod.rule-info.comps.rule-text.text-1"`时必须确认同一近邻容器含对应标签，避免误取保证金、评估价或加价幅度。公告价格只作回退，列表页明确价格优先于公告。
- 标题从公告/主标题抽取房屋坐落主干，不添加页面没有的楼盘或地址信息；删除权证号、公司名下前缀和`可贷款`提示。括号采用“明确无用才删除，不确定默认保留”：纯地址替换、权证说明可以删除，项目别名、期数、分区、地块、楼栋、单元、房号及`复式`等用途信息必须保留。清理中文地址与数字或字母编号之间的无意义空格，例如`龙岩大道中 29 号39 幢 15房产及B15附属用房、C0400、C0390、C0399号车位 可贷款`输出为`龙岩大道中29号39幢15房产及B15附属用房、C0400、C0390、C0399号车位`；不得改变编号字符或自行补充文字。详细规则见`references/title-community-rules.md`。
- 小区名称是Excel后处理的参考值，不回写为网页事实；无明确项目名称时只使用规定的`商住小区/工业区`回退值。
- V2统一通过`src/extractors/title.mjs`清洗标的名称，采集和Excel不得分别维护规则。小区名称通过`src/extractors/community.mjs`提取；面积通过`src/extractors/area.mjs`提取。
- 面积、标的名称和小区名称在机器可读记录中写入`_fieldEvidence`，至少保存最终值、来源区块、规则编号、置信度和是否需要复核；该内部证据默认不增加Excel列。

## 状态与金额

- 不再采集`正在进行`列表，也不输出`正在进行`工作表。
- `即将开始`：列表明确筛选为即将开始，或尚未取得结束结果；该分表不输出`成交金额`列。
- 阿里`是`：详情页右侧价格下方明确出现`本场已结束`；成交金额取`拍下价`。
- 阿里`否`：同一区域明确出现`本场已流拍`；成交金额为0。
- 同一文本疑似冲突时先判断`本场已流拍`。价格大小关系只能用于复核，不能改变结果文案的判定。
- `已撤回、已中止、已暂缓`归入`已结束`，成交金额为0。
- 只有列表显示已结束但未找到结果文案时，`是否成交=待核验`并进入复核。

拍卖时间只取页面或公告明确文字：即将开始取开拍端点，成交/流拍取最终竞拍结束端点。优先读取结果区的明确结束时间，再回退至竞买公告时间范围的结束值。缺失时写`未找到`，不得按24小时或60天推算。

## 城市和区域

优先从标的所在地或正式标题提取，其次用法院交叉确认。县级市写入`区域`。信息冲突或区域缺失时进入复核，不从推荐标的推断地点。

## 每日增量

状态文件高水位键固定为`平台:站点分类:状态`。每个平台只允许：

- 3个站点分类：`住宅用房、商业用房、工业用房`
- 2种状态：`即将开始、已结束`

因此每个平台需要6条高水位，两个平台共12条。旧状态中的`:正在进行`高水位加载时自动清除，不再读取、要求或更新。

首次或高水位缺失时：

1. 在打开Edge前逐项检查。
2. 缺哪一项就明确询问哪一项；不得猜测终止链接或继续翻页。
3. 用`seed-anchors --anchors-file FILE`分批写入；全部齐全后才能`run`。

后续扫描：

1. `即将开始`从`最新发布`第一页第一条开始，命中昨日该组高水位后停止。
2. 阿里`已结束`先选择`结拍时间由近到远`，再从第一页第一条开始，命中昨日该组高水位后停止。
3. 京东`即将开始`只选`预告中`并点击一次`最新发布`；京东`已结束`先取消`预告中`、只选`已结束`，再点击两次`结束时间`形成由近到远排序。
4. 每组本次扫描时的第一条规范链接成为下一日高水位。
5. 最大页数内未命中高水位、筛选未确认、详情失败或工作簿失败时，不推进任何高水位。

## 逐条保存与断点恢复

- 当日输出目录固定维护`采集进度.json`和`YYYYMMDD新增房源信息_采集中.xlsx`。
- `采集进度.json`是恢复依据，必须在每条详情成功或失败后原子覆盖，至少保存：
  - 当日运行计划和开始/最近更新时间；
  - 已成功完成的规范链接集合；
  - 每个“平台:站点分类:状态”已经扫描出的列表队列、昨日锚点、第一页链接及完成状态；
  - 当前正在处理的平台、分类、状态、标题和链接；
  - 候选新高水位、采集证据、失败项及尚未排序的记录。
- 临时Excel默认每条记录刷新一次，保留采集顺序，不做最终排序；增加`采集进度`表显示成功数、失败数、当前链接、最近保存时间和恢复说明。
- 重新运行相同日期、状态目录和输出目录时，先载入未完成进度：
  1. 将进度中的记录合并回候选状态；
  2. 复用已保存的列表队列；
  3. 跳过已完成链接；
  4. 仅重试失败链接并继续未处理链接。
- 用户中途补充字段或整理要求时，先更新代码，再以上述进度续爬。对已保存记录优先做离线加工；只有新字段确实无法从保存证据取得时才列入定向复核，不得默认全量重爬。
- 只有显式`--restart`才丢弃当日未完成游标。该选项不得由模型自行使用。
- 临时Excel被打开导致覆盖失败时，只记录警告，继续逐条保存JSON；不得因Excel文件锁而丢弃或回滚已采集记录。
- 全部任务无失败后，才生成最终排序工作簿、标记进度`已完成`并推进正式高水位。存在失败时标记`部分完成（可续爬）`，下次从失败项继续。

## 数据质量

以下情况进入`待人工复核.json`：

- 城市或区域为空；
- 标的类型不在`车位、住宅、别墅、商业、工业`中；
- 发拍次数、开始时间、结束时间无法确认；
- 面积或处置法院未找到；启用`--include-parties`时，债权人或债务人未找到也进入复核；
- 起拍价格无法转成数值；
- 评估价无法从平台详情页的明确标签转成数值；
- 成交结果为待核验，或成交但拍下价缺失；
- 地址、法院、省份相互冲突；
- 登录、验证码、空列表、锚点缺失、详情超时或阿里新版空壳页。

保留原始链接、字段来源和本次证据，不直接删除异常记录。
