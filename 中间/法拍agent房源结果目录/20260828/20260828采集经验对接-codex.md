> 以下为采集时必须遵守的**硬性规则**，每条都来自 20260828 实际踩坑验证。照此执行即可避免同类问题。每条规则可直接执行，不需要了解背景过程。

## 一、字段提取规则

**R1. 评估价：看到"市场价"也要抓。**
页面大量标的显示"市场价 ¥723,946"而非"评估价"。`评估价` 与 `市场价` 两个标签都提取，任一命中即算评估价。
```
评估价: ¥406,598.57   → 抓
市场价: ¥723,946      → 也是评估价，抓
```

**R2. 成交价：拍下价 = 成交金额。**
已结束页面显示"拍下价 ¥430,279"。成交判断：有拍下价+金额 → 成交；"本场已流拍" → 流拍；"本场已结束"但无拍下价 → 按未成交处理（备注保留证据）。**不要等"本场已成交"字样**（阿里页面通常不出现）。

**R3. 变卖标的：起拍价取"变卖价"或"变卖预缴款"。**
变卖页面没有"起拍价"栏。按 变卖价 → 变卖预缴款 顺序取起拍价。

**R4. 变卖公告 = 竞买公告，点击 tab 才能加载内容。**
变卖标的的 tab 叫"变卖公告"，普通标的是"竞买公告"。点击逻辑必须同时匹配两者，否则公告区永远"公告详情加载中"（37 字符占位）。
```js
const els = Array.from(document.querySelectorAll('a,button,div,li,span'))
  .filter(e => { const t = (e.innerText||'').trim(); return t==='变卖公告'||t==='竞买公告'; });
els[0].click();
```

## 二、面积获取规则（按优先级，缺面积必须按此顺序）

**R5. 面积来源顺序：详情页 DOM → 拍品介绍 → 竞买公告。**
1. 详情页 DOM（用 evaluate 读 `document.body.innerText`）：
```
房屋建筑面积([\d.]+)㎡
建筑面积[为是：:]([\d.]+)平方米
面积[为是：:]([\d.]+)
```
2. 拍品介绍："总建筑面积：80.78平方米。其中单元房74.03㎡,附属间6.75㎡" → 主面积取**总建筑面积**，分项写入备注。
3. 竞买公告（点击 tab 后等 5-8 秒）：单套为 `建筑面积X平方米` 或 `（面积：194.5㎡）`。

**R6. 多套合并拍卖：面积取公告表格"总计"行，分项写备注。**
公告表格表头：`序号/房产名称/建筑面积（平方米）/评估单价/评估总价`，最后一行为"总计"。例：9 套合并 → 总计 604.76㎡；15 套合并 → 总计 2290.86㎡。**禁止用单套面积当主面积**。

**R7. 面积缺失判断必须包含 4 个值：`None`、`''`、`未找到`、`待补采`。**
漏掉 `待补采` 会导致该条永远不被补采（实测踩坑）。

## 三、类型与筛选规则

**R8. 车位不采集。**
纯车位/车库/储藏间/柴火房/杂物间标的（名称不含主房产词）一律排除，不进待采清单、不进数据。**"住宅/商业+附带车位/附属间"保留**（主标的是房产）。
```python
is_pure_car = (re.search(r'车位|车库|储藏间|柴火房|杂物间', name)
               and not re.search(r'房产|住宅|单元|室\b|店面|商铺|商场|办公|别墅|写字楼|厂房', name))
```

**R9. 待确认/其他/车位类型 → 归为住宅**（HTML 统计区只有住宅/商业/工业三栏）。

**R10. 城市判断：县级市/县也归属城市。**
名称含"福建省闽侯县/福清市/连江县/罗源县/闽清县/永泰县/平潭县" → 福州；"安溪县/惠安县/永春县/德化县/南安市/晋江市/石狮市" → 泉州。**不要只认"福州市/泉州市"字样**。

**R11. 已撤回/中止/暂缓的标的要删除**，不保留在数据中。

**R12. 小区名称是必采字段**（页面标题/拍品介绍有），不得留空。可先用历史 HTML 的小区名池做反向匹配（标的名称包含即命中），剩余再开网页。

## 四、工具使用规则

**R13. 优先用 `evaluate` 读 `document.body.innerText`，不要只信 snapshot。**
snapshot（无障碍树）经常不渲染价格、面积、调查表字段。evaluate 提取价格/面积/法院更可靠。

**R14. navigate 后等 8-10 秒再读取**（6 秒常拿到空快照）。快照长度 < 200 视为未加载完，等 6 秒重试一次。

**R15. 竞买公告容器：`document.getElementById('NoticeDetail')`**，点击 tab 后 innerText 有内容才算加载完成。

---

## 五、运行规则（速度与断连）

**R16. bsk session 会超时/被清理**（报 `session not registered` / `operation interrupted by user`）。长任务每 20-30 分钟检查一次 session，断了重启后按断点续采（进度文件里有已完成链接）。

**R17. 每采一条立即保存**（补采记录 JSON 边采边写），不要等整批结束——断电/断连不丢数据。

**R18. 一次只跑一个采集脚本**，禁止多进程并发操作同一 session（会互相打断）。

**R19. 后台跑不要用 `| tail` 管道**（缓冲看不到实时进度），直接 print 到日志文件。

**R20. 检测到"验证"字样立即 `bsk request-help` 交人工处理**，不硬等、不盲点。

**R21. 每条标的耗时约 10-15 秒**（navigate 8s + 读取），100 条约 25 分钟，按此规划任务时长。

## 七、数据口径

**R25. 评估价保留两位小数（406,598.57）；起拍价/成交价为整数元。**

**R26. 起拍单价 = 起拍价 ÷ 面积（元/㎡，取整）；折扣率 = 起拍价 ÷ 评估价。**

**R27. 面积 > 10000㎡，或单价 > 10万/㎡ 或 < 500/㎡，备注必须写"数据疑似有误"及原因。**

**R28. 上新列表里可能与上一日重复，必须按"昨日累积 HTML 链接集合"去重（不能只按本次补采记录去重）。**
阿里上新列表按发布时间排序，昨天刚发布的"即将开始"标的今天还在列表前部。20260828 实测：170 条待采中有 **60 条**与 827 累积 HTML 重复（59 条为昨日入库），全部为阿里即将开始。合并入库前必须：
```python
old_links = 昨日累积HTML全部链接  # 827 的 泉州/福州房源上新.html
new_list = [x for x in 今日列表 if x['链接'] not in old_links]  # 而非只排除本次补采记录
```
判定为误爬的删除，并保留删除清单（`20260828_重叠误爬删除清单.json`）。

## 八、高效运行路径（照此执行：快、稳、不断）

> 规则解决"做什么"，本节解决"怎么跑"。按下面 5 步走，全程后台脚本 + 断点续采，不会慢、不会断、不会重复采。

### P1. 整体流水线（5 步，顺序不可乱）

```
① 列表抓取     → 脚本一次性抓齐四路列表（含标题）→ 存 ali_list_links_v2.json
② 生成待采清单 → 到高水位为止 → 按URL与已采去重 → 排除纯车位 → 输出待采JSON
③ 批量采集     → 后台脚本逐条开页面 → 每条立即写盘 → 进度文件记已完成
④ 缺失定向补采 → 统计缺字段记录 → 只重开这些页面（绝不重新全采）
⑤ 合并生成     → 阿里+京东合并 → 按URL去重 → 生成 manifest
```

**为什么 ①② 要先做？** 先把"采什么、采多少"定死，采集脚本只认清单跑，不会边采边想、不会漏采重复采。codex 常见病就是直接开页面一条条采，中途才想起过滤——务必先建清单。

### P2. 批量采集脚本骨架（稳定版，直接照抄结构）

```python
# 核心设计 5 条：
# 1) 从待采清单读，跳过"已完成链接"集合 → 天然断点续采（断了重启接着跑）
# 2) 每条最多 3 次重试：第 1 次等 8s，第 2 次等 12s，仍空跳过记入缺失清单
# 3) 每条采完立即 append 补采记录JSON + 更新进度文件 → 断电不丢
# 4) 用 evaluate 读 document.body.innerText 一次提取全部字段（见 P4）
# 5) 缺字段不中断流程，记入"待补清单"，统一走第④步定向补采

for link in 待采清单:
    if link in 已完成: continue
    ok = False
    for attempt in (8, 12):            # 等待秒数递增
        bsk.navigate(link); time.sleep(attempt)
        data = bsk.evaluate(JS_EXTRACT) # P4 模板
        if data 非空: ok = True; break
    if not ok: 待补清单.append(link); continue
    rec = 组装字段(data)
    补采记录.append(rec); 立即写盘
    已完成.add(link); 立即写进度
```

### P3. 速度与稳定性要点（今天的实测参数）

| 项 | 正确做法 |
|----|---------|
| 单条耗时 | navigate 后等 **8-10 秒**（6s 常拿空），空结果重试 1 次，单条约 10-15s |
| 批量规模 | 100 条约 25-30 分钟；**后台跑**，别在前台等 |
| session 维护 | 每 20-30 分钟查一次 session，断了重启，靠进度文件续采 |
| 并发 | **一次只跑一个脚本**，禁止两个进程抢同一 session |
| 日志 | 不用 `\| tail` 管道（缓冲看不到进度），print 直接进日志文件 |
| 验证码 | 见"验证"字样立即 `bsk request-help` 交人工，不硬等 |

### P4. 字段提取模板（一次 evaluate 全拿，别再逐字段 grep snapshot）

```js
(() => {
  const t = document.body.innerText;
  const g = r => { const m = t.match(r); return m ? m[1].replace(/,/g,'') : null; };
  return JSON.stringify({
    start:   g(/起拍价[^0-9]*¥?\s*([\d,]+)/) || g(/变卖价[^0-9]*¥?\s*([\d,]+)/) || g(/变卖预缴款[^0-9]*¥?\s*([\d,]+)/),
    assess:  g(/评估价[^0-9]*¥?\s*([\d,.]+)/) || g(/市场价[^0-9]*¥?\s*([\d,.]+)/),   // R1
    deal:    g(/拍下价[^0-9]*¥?\s*([\d,]+)/),                                        // R2
    area:    g(/房屋建筑面积\s*([\d.]+)\s*㎡/) || g(/建筑面积[为是：:]\s*([\d.]+)\s*平方米/),
    court:   g(/[\u4e00-\u9fa5]{2,}(?:人民法院|法院)/),
    rounds:  g(/(一拍|二拍|变卖|再次拍卖)/),
    bid:     g(/(\d+)\s*次出价/),  bidder: g(/(\d+)\s*人报名/),
    end:     g(/结束时间\s*([\d\/\s:]+)/),
    title:   (document.title || '').slice(0, 80),
  });
})()
```

### P5. 缺失字段补采策略（先本地、后网页、绝不重采）

| 缺失 | 优先级 | 做法 |
|------|--------|------|
| 评估价 | 本地→网页 | 页面取"市场价"（R1）；补采时只开缺的页面 |
| 面积 | 网页三级 | 详情DOM → 拍品介绍 → 竞买公告（R5-R6） |
| 小区名 | **本地优先** | ① 用历史 HTML 小区名池反向匹配（标的名称包含即命中，本地秒级，一次补几十条）② 剩余再开网页 |
| 其他 | 定向 | 统计缺字段 → 只重开这些链接，**禁止全量重采**（浪费 20 倍时间） |
