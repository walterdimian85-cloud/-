# 采集、复核、清洗与交接硬性规则

规则版本：1.5  
生效日期：2026-08-31  
规则所有者：用户（老大）  
适用范围：任何承担采集、复核、清洗、去重、日期归属、排序和产物交接任务的智能体、程序或人工工作台。

## 0. 规则锁与优先级

1. 本文件是采集至交接阶段的唯一硬性规则正本，优先级高于日期日志、memory、历史脚本注释、旧manifest、旧采集经验和智能体自行总结。
2. 除非用户明确说“修改硬性规则”并指出具体条款，否则任何智能体不得修改、弱化、覆盖或绕过本文件。
3. 用户只是在某一批次临时调整日期、高水位或范围时，仅写入当批任务参数，不得擅自改成本文件的永久规则。
4. 发现本文件与旧文件冲突时，执行本文件并报告冲突；不得静默选择旧规则。
5. 修改本文件前必须重新读取最新内容，并在文末变更记录写明日期、用户原话摘要和修改条款。
6. 本规则约束任务阶段，不绑定具体智能体、模型、程序或工作台。任何执行者领取本阶段任务后均适用同一输入、输出、权限边界和验收标准。
7. 同一执行者可以在用户授权下连续承担多个阶段，但必须逐阶段通过验收；更换执行者不得跳过、合并或转移尚未完成的判断责任。

## 1. 数据准备阶段职责

领取数据准备阶段任务的执行者负责：

1. 确认任务参数和上新归属日期。
2. 建立带顺序的固定采集队列。
3. 完整采集并保存原始事实与证据。
4. 补齐和复核字段。
5. 标准化地区、小区、法院、地址、价格、面积、轮次、状态和日期。
6. 依据正确高水位清除超采，依据复合键去重。
7. 排好最终顺序。
8. 生成唯一的产物输入JSON和manifest。

数据准备阶段不生成HTML、格式化Excel或同步飞书。产物生成阶段不得接手尚未完成的字段判断、去重、日期归属和排序工作。

## 2. 开始任务前必须确认

开始采集前必须向用户确认并记录：

- 任务类型：新采集或断点续采集。
- 平台：阿里资产或京东拍卖。
- 城市：泉州、福州或二者。
- 类型：住宅、商业、工业。
- 状态：上新、已结束或二者。
- 每条路线的列表链接、排序方向和旧高水位。
- 本批上新分别归属哪一天。
- 输出日期目录和是否允许创建该日期目录。

上新日期不得按采集日自动推断。周一补采周六、周日数据时，必须按用户指定分别写入周六、周日的上新归属日期。成交和流拍不使用上新归属日期，而按真实结束日期归档。

## 3. 高水位与队列

1. 高水位是上一批采集范围的边界，高水位标的本身属于上一批。
2. 本批从列表顶部开始，采集到旧高水位之前；不采旧高水位本身及其后的旧记录。
3. 新高水位是本批开始扫描时列表的第一条。即使第一条最终因纯车位、纯车库等原因不进入产物，它仍是下一批高水位。
4. 必须先保存列表顺序、规范URL、列表标题、城市、类型和状态，再开始详情采集。
5. 改过排序方向、点击次数或高水位后，必须重新抓取列表并重建队列。
6. 因高水位错误导致超采时，按用户最终确认的正确高水位和原列表顺序删除超出范围的记录；不得用“是否存在历史HTML”替代高水位边界判断。
7. 采集队列不得因为某ID曾出现在上新HTML中就排除现在的成交或流拍结果。

阿里固定参数：上新使用`sort=504`，结束使用`sort=600`，`hPurpose`同时包含住宅、商业、工业；默认不含破产清算。列表状态只用于建队列，最终状态以详情页证据为准。

## 4. 采集与断点

1. 每条记录完成后立即追加保存原始记录并更新进度，不得整批结束后一次性写盘。
2. 页面切换后必须核对规范URL、页面标题和队列标题一致，防止读取上一页残留。
3. 详情已有完整可靠字段时直接保存并进入下一条，不打开公告。
4. 仅字段缺失时滚动到竞买公告或变卖公告区域并触发加载。
5. 公告未加载完成时最多等待10秒；10秒内加载完成则只补缺失字段。
6. 等待满10秒仍未加载，字段写`待补采`并记录链接、字段和页面状态，然后进入下一条。
7. 公告完整加载并重新读取后仍无证据，才写`未找到`。
8. 整批结束后只定向补采缺失链接，不重新全量采集。
9. 登录、滑块、短信码或验证码必须暂停并交给用户；禁止报名、出价、收藏、提醒和联系机构。

## 5. 必采字段

每条有效记录至少包含：所在省份、城市、区域、原始标的名称、标准地址、小区名称、标的类型、平台、发拍次数、拍卖时间、状态/是否成交、处置法院、面积、起拍价格、评估价、成交金额、竞买记录、报名人数、备注、规范网站链接、字段证据、上新归属日期或真实结束日期。

保证金、加价幅度、围观人数不是项目字段，不主动采集、不保存、不校验、不为其打开公告。

成交和流拍标的的报名人数是必采字段。

### 5.1 缺失、未披露与房间格局例外

1. 除房间格局外，必采字段出现`null`、空字符串、`未找到`、`待补采`或`待核验`，均视为尚未完成，必须进入缺失字段回档清单。
2. 缺失字段回档清单至少包含：规范链接、原始标题、城市、区域、数据阶段、真实结束日期或上新归属日期、缺失字段、已检查证据位置和当前状态。
3. 对回档链接重新检查详情、调查表、拍品介绍和已完整加载的公告后，网页确实没有披露时，字段写`未披露`并保存已检查位置与原文证据；`未披露`与“尚未检查完整”必须严格区分。
4. 房间格局为可选字段。网页未明确披露时允许留空，不进入缺失字段回档清单，不阻断交接，也不得根据面积、户型图或常识推测。
5. 补齐起拍价、成交价或面积后，必须重新计算依赖字段，包括起拍单价、折扣率、成交单价和溢价率；不得只补原始字段而保留旧计算值。
6. 产物生成阶段发现未解决缺失时，只能输出缺失清单并退回本阶段，不得自行打开网页、猜值或静默留空。

## 6. 面积、价格和状态

1. 面积证据顺序：详情页正文/调查表 → 拍品介绍 → 竞买公告或变卖公告。
2. 面积关键词优先级：建筑面积 → 房屋建筑面积 → 总建筑面积 → 产权建筑面积。
3. 土地、宗地、占地、分摊、公摊面积不得作为主面积。
4. 住宅或商业与储藏间、附属间、车位、车库一并处置且公告给出合并建筑面积时，直接采用该建筑面积，不强制拆分，并在备注保留原文。
5. 独立储藏间保留并采集其明确建筑面积，不因“纯储藏间”排除。
6. 多套同类房屋合并拍卖有总计面积时取总计；无总计时不得擅自混加不相关面积。
7. 评估价和市场价按项目口径统一保存为人民币元；保证金和起拍价不得冒充评估价。
8. 变卖无起拍价时按“变卖价 → 变卖预缴款”取起拍价格。
9. 页面有明确拍下价即记成交金额；明确流拍即记流拍；状态证据冲突则进入复核。
10. 住宅或商业面积大于10000㎡，或起拍价÷面积大于100000元/㎡、小于500元/㎡，备注必须写“数据疑似有误”及具体原因。

## 7. 小区、地区和法院

1. 城市和区域必须使用页面权威所在地及已知区县集合核对，不得使用宽松正则截取“在永春”等错误片段。
2. 小区名称优先级：页面明确“小区名称” → 卡片原文“房产小区名” → 标题/公告中的正式项目名 → `E:\归档\法拍\后台数据\小区名称清单.txt`精确匹配。
3. 道路、街巷、社区、街道、镇、村不是小区名称。
4. 禁止把标题或地址的截断片段、行政区片段（如“址在永春县五里”）写入小区名称。若标题/公告和小区名称清单能完整匹配项目名，必须写入该完整匹配名；无法完整匹配时写`商住小区`、`工业区`或`未找到`并列入缺失/复核清单，不得用截断文本凑值。
5. 法院先保存页面全称，再生成标准展示值；不得凭城市推断法院。`福建省泉州市中级人民法院`、`福建省福州市中级人民法院`分别展示为`泉州市中级人民法院`、`福州市中级人民法院`；其他以`福建省`、`泉州市`或`福州市`开头的非中级人民法院展示值，删除相应开头前缀；其他省级中级人民法院（如`江苏省南京市中级人民法院`）保留全称。
6. 小区名称出现“XX一期/二期＋区块附加名”且分期名称已能准确定位小区时，删除该期号后的区块附加名；例如`万科金域滨江一期爱乐佳园`标准为`万科金域滨江一期`。此规则只作用于小区名称，不得删改标准地址中的完整定位信息。
7. 交接前必须逐条检查小区名称与处置法院：小区名称不得为截断标题/地址，法院展示值必须符合本节第5条；未通过不得生成唯一输入。
8. 小区名称自动截断拦截：名称少于3个字符、含“址在”等地址引导词、呈现“在…区/县/镇”等行政地址片段、以区/县/市/镇/村/路/街等泛地址词结尾，或只是标准地址的明显截断前缀时，均不得写入唯一输入。页面明确、名称清单精确命中或用户明确人工核证的例外，必须在字段证据中注明；否则回到本节第4条的`商住小区`、`工业区`或`未找到`处理，并进入缺失/复核清单。

## 8. 标准完整地址

原始标的名称必须永久保留；标准地址单独生成。

标准地址按以下顺序处理：

1. 删除开头重复的省级、地级市前缀，例如`福建省`、`江苏省`、`福州市`、`泉州市`。
2. 删除区域列已经表达的区、县、县级市名称，例如`晋江市`、`鼓楼区`、`安溪县`。
3. 保留街道、镇、村、社区、道路、小区/项目、楼栋、单元、房号、商铺号和共同处置车位编号等定位信息。
4. 删除权利人前缀、权证号、可贷款等非地址提示。
5. 括号默认删除；括号内包含不可缺少的楼栋、单元、房号等定位内容时，只提取有效内容并去掉括号。旧地名、旧项目名和解释性内容不自动保留。
6. 删除“的＋尾缀词”整体，尾缀包括：`房产`、`不动产`、`房地产`、`及室内家具家电`、`及屋内物品`；不得先删除尾缀而遗留地址末尾孤立的`的`字。处理后若地址末尾仍为孤立`的`，一律删除。
7. 清理无意义空格和重复标点。
8. 用户以后明确新增尾缀时再修改本文件，不得自行扩展删除词表。

## 9. 排除对象

仅排除：

- 单独拍卖的纯车位。
- 单独拍卖的纯车库。
- 已撤回、已中止、已暂缓。
- 超出用户明确任务范围或正确高水位范围的记录。

不得排除：

- 独立储藏间。
- 住宅、商业或工业与车位、车库、储藏间共同处置的整体标的。
- 历史上新、本次成交或流拍的状态迁移记录。
- 同一资产的一拍、二拍、变卖等不同轮次。

所有排除必须保存规范链接、原始标题、路线和具体原因。

## 10. 去重与状态迁移

1. 上新只与历史上新比较，结果只与历史结果比较。
2. 去重键至少包含：平台＋规范标的ID/URL＋发拍次数＋数据阶段＋拍卖开始/结束时间。
3. 只有上述关键项一致才能自动判为重复。
4. 历史上新转为成交或流拍是状态迁移，必须保留结果。
5. 同一ID不同轮次、不同时间或不同阶段不得删除。
6. 关键项缺失或冲突时宁可保留并进入人工复核，不得自动删除。
7. 地址和标题只能作为辅助核验，不得单独作为删除依据。

## 11. 日期与排序

上新：按用户指定的上新归属日期降序 → 固定区县顺序 → 一拍 → 二拍 → 变卖。  
结果：按真实结束日期升序 → 成交/流拍分组 → 固定区县顺序 → 一拍 → 二拍 → 变卖。

泉州区县顺序：丰泽→鲤城→洛江→晋江→石狮→南安→惠安→台商→泉港→安溪→永春→德化。  
福州区县顺序：鼓楼→仓山→台江→晋安→闽侯→福清→马尾→连江→长乐→罗源→闽清→永泰→平潭。

## 12. 产物交接契约

交接前必须完成字段质检、缺失检查、日期归属、超采清理、复合去重和排序。产物生成阶段不得承担这些判断。

同一批次只生成：

- 一个唯一的`三产物输入.json`。
- 一个`manifest.json`。

manifest至少写明：规则正本路径、规则版本、批次日期、上新归属日期映射、结果日期规则、地区、平台、数据来源、各状态数量、排除清单、重复清单、缺失清单、排序规则、目标路径、是否同步飞书、是否允许覆盖和回滚依据。

大宗标的必须保留在常规上新/结果数据中，同时标记进入大宗专表，不得二选一。

## 13. 交接前硬性验收

- 逐城市×日期×状态统计数量。
- 检查规范链接和复合去重键。
- 检查上新归属日期和真实结束日期。
- 检查区县、轮次和排序。
- 检查小区名称库匹配结果。
- 运行小区名称截断拦截：命中地址引导词、行政地址片段、泛地址尾缀或明显截断前缀的记录，必须列出链接并阻断交接；有页面、清单或用户人工核证例外时必须有对应证据。
- 检查标准地址前后缀：不得残留省级前缀、`的房产/不动产`等尾缀或末尾孤立`的`字。
- 检查处置法院是否符合§7.5的前缀展示规则；不得把应删除的`福建省`、`泉州市`、`福州市`前缀带入唯一输入。
- 检查面积、价格单位及异常阈值。
- 检查成交/流拍报名人数。
- 检查排除项有完整理由。
- 缺失项为0，或用户已明确接受的人工清单完整列出。

未通过验收不得进入产物生成阶段。
