# 法拍资产项目通用智能体工作指令

本文件是所有智能体进入 `E:\dsh` 后的统一入口。任何智能体都必须先判断自己处于哪个阶段、领取哪一种任务、使用哪些路径，再开始工作。

## 硬性规则正本（必须先读）

- 采集、复核、清洗、去重、日期归属、排序和产物交接：必须读取 `E:\dsh\中间\采集复核与交接硬性规则.md`。
- HTML、Excel、飞书生成、修改和一致性验收：必须读取 `E:\dsh\中间\产物生成硬性规则.md`。
- 两份正本优先级高于本通用入口、日期日志、memory、历史脚本注释和旧manifest。除非用户明确声明修改硬性规则，否则任何智能体不得修改、弱化或覆盖正本。
- 两份规则只绑定任务阶段，不绑定Codex、WorkBuddy或其他具体执行者。谁领取对应阶段，谁就遵守该阶段的输入、输出、权限边界和验收标准；同一执行者经用户授权可以连续承担多个阶段，但不得跳过阶段验收。
- 规则正文是可复用要求，变更记录只作版本索引，不得把日期日志、历史事故、批注或某个智能体的处理习惯当作补充规则。发现字段质量问题时，必须在对应阶段正本中查找明确条款；没有条款则暂停询问用户。
- 禁止把任何智能体的memory、私有提示词、个人经验、隐藏默认参数或旧对话习惯当成项目规则。未写入两份硬性规则、当前manifest、已验收模板或用户当前明确指令的内容，一律不执行；发现规则未定义时先报告待确认项，不得自行发挥。
- 承担产物生成任务时，除读取`产物生成硬性规则.md`外，还必须核对manifest中的规则版本与正式生成工具及版本；使用模板时再核对模板路径与版本/哈希。未使用模板时，只能使用产物硬性规则中已锁定的视觉参数，不得用私人模板、临时脚本或惯例补位。

## 一、进入项目后的第一句话

> 请告诉我这次需要我领取什么任务：①采集或断点续采集，②AI字段复核，③缺失补齐/去重/日期归属调整，④准备产物交接，⑤生成或修改产物，⑥故障诊断/数据恢复，⑦目录整理/归档，还是其他任务？请同时告诉我任务日期、地区、平台，以及是否允许修改文件。

在用户回答前，只能查看目录和文件状态，不得启动采集、修改数据、生成产物、覆盖或删除文件。

## 四、按阶段领取任务

### 阶段1：采集或断点续采集

适用任务：启动采集、重新采集、断点继续、高水位调整、浏览器验证码、采集浏览器故障。

- 程序路径：`E:\dsh\原料\法拍资产Agent-交付版V3.7`
- 配置路径：`E:\dsh\原料\法拍资产Agent-交付版V3.7\config\agent.local.json`
- 数据输出：`E:\dsh\中间\法拍agent房源结果目录\YYYYMMDD`
- 允许：按用户指定的平台、地区、状态和高水位采集；查看队列与运行日志；按断点继续。
- 禁止：未经授权重新采集、清空断点、改最终 HTML/Excel、同步飞书或生成产物。
- 完成标准：说明成功/失败数量、断点状态、验证码或登录问题、缺失队列以及原始输出路径。

使用 browser-skill 时，必须同时读取 `E:\dsh\原料\browser-skill采集工作指令.md`；使用 DSH浏览器助手时，必须同时读取 `E:\dsh\原料\DSH浏览器助手采集工作指令.md`。两者均只写入当前日期批次目录，不能覆盖 Agent 原生断点和原始记录。

无论由哪个智能体、程序或工作台临时代采，开始采集前都必须完成以下交接，不得依赖上一个对话的记忆：

1. 读取本文件和所用工具的专用采集指令。
2. 从用户、本日进度文件或 Agent 配置确认日期、平台、城市、状态、列表链接、排序方向和高水位；历史日志中的高水位只能作参考，不能自动沿用。
3. 先生成固定待采清单，再开始详情采集。待采清单先规范化URL、保存列表顺序并按正确高水位划定范围；只排除硬性规则明确不采的纯车位、纯车库等对象。不得因链接出现在累计HTML中而跨阶段排除结果记录。
4. 读取当天同工具的进度文件，跳过已完成链接；每采完一条立即保存记录和进度，断线后从断点继续，不得清空重跑。
5. 单条字段不完整时只把该链接加入缺失清单；整批结束后定向补采缺失项，不得重新全量采集。
6. 长批次必须在进度文件持续记录总数、完成数、剩余数、当前链接和更新时间；按用户要求或每完成一批主动汇报，但汇报不得暂停后台采集。除验证码、登录、风控或缺少关键任务参数外，不得等待用户发送“继续”。
7. 只有待采清单全部处理、记录与进度都已落盘后才能回复“采集完成”。进程意外停止时立即说明真实原因并从断点恢复，不能在没有活动进程时声称仍在运行。

如果用户只要求复核，绝对不能进入本阶段，也不得启动采集进程。

### 阶段3：数据整理与质量检查

适用任务：缺失补齐、重复删除、日期归属调整、结束时间纠正、今日与昨日结果比对、生成缺失清单。

- 工作输出：优先写回当前批次中已有的清单、JSON或Excel；没有用户授权不得创建新目录。

- 完成标准：明确报告新增、重复、删除、回归上一日期、仍缺失和异常的数量及链接。

阶段责任固定如下：阶段1负责划定正确高水位范围、规范URL、排除明确不采对象并保存断点；阶段3负责字段质检、跨来源合并、复合去重、状态迁移、日期归属、排序和最终删除清单；阶段5只消费已整理好的唯一输入，不得在生成产物时临时猜测、去重或悄悄过滤。责任跟随阶段，不跟随执行者名称。

如果同一日期存在 `YYYYMMDD（1）`、`YYYYMMDD（2）` 等目录，不得凭名称猜测主批次。先读取目录说明、manifest、状态文件和时间戳；仍无法确认时询问用户。

## 五、采集、字段与过滤硬性规则

- 面积查找顺序：详情页正文/调查表 → 拍品介绍 → 竞买公告或变卖公告；页面字段不足时必须到公告区，公告尚未加载时按专用采集指令等待后再判定。
- 面积关键词优先级：建筑面积、房屋建筑面积、总建筑面积、产权建筑面积；同一证据出现总计行时，多套同类房产合并拍卖取总计面积，并在备注保留分项原文。
- 土地、占地、分摊、公摊面积不得作为主面积。
- 住宅或商业与附属间、储藏间、车位、车库一并处置且公告给出一个合并建筑面积时，主面积直接采用该建筑面积，不强制拆分；若分别给出主房与附属物面积，则优先采用公告明确的总建筑面积，没有总计时取住宅/商业主面积，并把完整分项原文写入备注。
- 评估价字段同时识别“评估价”和“市场价”，页面的市场价按本项目口径写入评估价；保证金、起拍价不得代替评估价。
- 变卖标的没有起拍价时，按“变卖价 → 变卖预缴款”的顺序取起拍价格。
- 已结束标的有“拍下价”即把拍下价记为成交金额；“本场已流拍”记为流拍；只有“本场已结束”但没有拍下价时记为未成交并保留证据。
- 成交和流拍标的必须采集报名人数；已撤回、已中止、已暂缓的标的不进入交接与产物，保留在删除/异常清单中。
- 保证金、加价幅度、围观人数不属于项目字段，上新和结果均不主动提取、不保存、不校验、不写入备注或产物；页面快照偶然包含时直接忽略，不为这些字段打开公告或增加网页操作。
- 小区名称是必采字段：先从标题、正文和公告提取，再用历史 HTML 小区名池做精确反向匹配；仍无可靠证据时明确写“未找到”，不得猜测。
- 单独拍卖的纯车位、纯车库不采集；独立储藏间保留。住宅/商业/工业与车位、车库、储藏间等附属物一并处置时整体保留。
- “待确认/其他/车位”不能为了适配统计表而一律改成住宅；必须先按页面事实分类。纯附属物按前述规则排除，确实无法分类则写待核验。
- 城市必须覆盖所属县、县级市，不得只靠标题中是否出现“福州市”或“泉州市”判断。
- 住宅或商业面积大于10000㎡，备注必须包含“数据疑似有误”及具体原因。
- 起拍价÷面积大于100000元/㎡或小于500元/㎡，备注必须包含“数据疑似有误”及具体原因。
- 结束时间排序方向必须与用户指定的高水位方向一致；调整排序后必须重新建立本次队列并说明。
- 同一标的去重使用平台＋规范标的ID/URL＋发拍次数＋数据阶段＋拍卖开始/结束时间；跨阶段状态迁移和不同轮次不得删除，地址和标题只能作为辅助证据。
- 高水位是上一次采集范围的边界，边界标的本身属于上一批次。本次待采为列表起点到高水位之前的新记录；命中高水位即停止，不采高水位及其后的旧记录。若列表排序方向或页面状态与该口径不一致，先暂停并重建队列。
- 阿里上新列表使用 `sort=504`，结束列表使用 `sort=600`，用途参数必须同时包含住宅、商业、工业；实际列表可能混入其他状态，最终状态以详情页为准。
- 每条导航后必须核对当前规范 URL、页面标题和待采清单标题相符，防止读取上一页残留造成串数据。
- 缺失判断必须同时识别 `null/None`、空字符串、`未找到`、`待补采`；缺失补齐只重开缺失链接。

## 六、文件操作硬性规则

- 所有路径以本文件列出的当前真实路径为准；操作前仍须使用只读方式确认路径存在。
- 不创建新的顶层目录、日期目录、“最终版”“最新版”“临时版”目录或重复交接目录。
- 新文件只能在任务所属的既有目录中生成；无法判断归属时先询问用户。
- 先读后写，覆盖前保留可恢复依据；已有结果必须从断点继续，不得清空。
- HTML一律严格按UTF-8读写；不得使用依赖Windows PowerShell 5.1默认编码的写入命令。正式HTML修改后必须运行共享HTML验收脚本，失败即停止后续产物和飞书步骤。
- 文件命名沿用当前批次和现有命名规则，不自行改名造成路径断链。
- 删除、覆盖、批量去重或移动前，必须先确认确切对象和影响范围。
- 不把采集、复核、生成、诊断和归档混成一个任务；跨阶段必须获得用户明确授权。

## 七、完成任务后的固定回报

完成后必须向用户报告：

- 领取的任务和所处阶段；
- 实际读取的输入路径；
- 实际修改或生成的文件；
- 数据总数、缺失数、重复数和异常数；
- 未完成事项及原因；
- 是否启动过采集、是否修改过源数据、是否同步飞书；
- 用户下一步应执行什么。

如果任务执行过程中发现自己领取错了阶段，应立即停止，说明当前情况，并重新向用户确认任务，不得继续跨区操作。
